ISSUE IDENTIFIED
================

You were getting "Invalid credentials" even though the password was correct in the 
database. This happened AFTER switching from SHA256 to BCrypt hashes.

ROOT CAUSE:
───────────

The C# code in DatabaseService.cs had TWO different bugs:

❌ BUG #1: SHA256 Hashing (OLD CODE)
   - When you logged in with "password"
   - C# hashed it with SHA256 → produces 64-character hex string
   - Database had BCrypt hash → $2a$12$DQ4skCsan4rSeCh9...
   - These NEVER match → "Invalid credentials"

❌ BUG #2: Direct Hash Comparison (OLD APPROACH)
   - Code was doing: WHERE password_hash = @passwordHash
   - This is wrong for BCrypt hashes!
   - BCrypt hashes use salting - same password always produces different hashes
   - Must use BCrypt.Verify() function, not direct comparison

HOW BCRYPT WORKS (Why it's different)
=====================================

SHA256 (OLD - BROKEN):
└─ Same input always produces same output
└─ password "password" → always "5e884898da28047..." (same every time)
└─ Problem: Can be directly compared with == operator
└─ NOT SUITABLE for passwords!

BCrypt (NEW - CORRECT):
├─ Includes random salt in hash
├─ Same password produces DIFFERENT hash each time
├─ Example:
│  └─ Run 1: password → $2a$12$DQ4skCsan4rSeCh9IY.iE..nJ61CeC1vJuL6I1xl2gH71DfmdoL/a
│  └─ Run 2: password → $2a$12$vR/EHPfLivZbM4DYHEBQWuh7gUfAX1ZI5F5V5I5V5I5V5I5V5I5I5
├─ These look totally different but are BOTH valid for "password"!
├─ Solution: Use BCrypt.Verify(plaintext_password, stored_hash)
└─ Returns: true if password matches, false if not

WHY THIS HAPPENED (EXPLANATION)
================================

"Everything was working before, why broke now?"

BEFORE (SHA256):
- All passwords hashed with SHA256
- Direct comparison worked (though insecure)
- No errors because everything was SHA256

NOW (BCrypt):
- Database has BCrypt hashes
- Code was still using SHA256
- SHA256("password") ≠ BCrypt("password")
- Auth failed because hashes didn't match

The code was never updated when you switched to BCrypt hashes in the database!
